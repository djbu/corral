# corral M1 design — daemon skeleton + interactive sessions

> Intended location: `docs/design/m1.md`. Read `RUNBOOK.md` §3/§5/§10 and `docs/spike-notes.md` first. This document resolves every structural choice for M1; the implementer should not need to invent architecture.

> **Step 0 verification results (see `spike/verify/NOTES.md`) — all three assumptions CONFIRMED, design stands as written:**
> - **V1:** interactive `--resume <id>` direct-loads, no picker; sessions interrupted mid-turn resume as a first-class state (`isAbortedMidStream` rendered in the TUI). §3.5/§7.3 unchanged.
> - **V2:** `--settings` merges key-by-key — a pinned key wins, unlisted user-level keys (chiefly `apiKeyHelper`) keep flowing. §7.4 unchanged. Open one-liner: whether `{"hooks": {}}` clears or merges the user hook map is untested; if M2 sees user hooks leaking into supervised sessions, that's the first thing to check.
> - **V3:** SIGTERM to the process group flushes the in-flight turn as **partial-but-marked** (`isAbortedMidStream: true` + synthetic `interruptedByShutdown` record), exiting in <1s — graceful shutdown is NOT the total loss SIGKILL is. Revise §3.7's known-limitation wording from "turn loss on restart" to "partial-but-marked on graceful restart; total loss only on hard crash." Verified in `-p` mode; TUI-mode signal write-path is the remaining gap, noted for M3's chaos suite.

## 0. Corrections to the M1 brief (read this first)

**The brief's premise "children survive daemon death (they're setsid'd)" is not what the spike showed.** `spike/pty/NOTES.md` "Other things worth knowing" documents the opposite: the spike daemon's SIGTERM path explicitly did `kill(-childPid, SIGTERM)` then `SIGKILL`, and *that* is why zero orphans were observed. The setsid'd child was never tested against daemon `SIGKILL`. On both darwin and linux, when the last PTY **master** fd closes (which happens when the daemon dies), the slave side hangs up and the foreground process group gets SIGHUP — a TUI normally dies. So: child survival across ungraceful daemon death is **unverified in both directions**, and M1's recovery path must handle both branches. It does (§3.5).

**`claude --session-id <uuid>` exists** (verified against claude 2.1.224 `--help`). Corral generates the session UUID and passes it on first spawn, so the resume key is known *before* the child starts. This deletes the "we never learned the session_id, so we can't resume" failure branch entirely, and demotes `internal/claude/sessions` to a verification-only helper in M1 — **no newest-`.jsonl`-sniffing on the critical path.**

**claude's TUI emits 24-bit truecolor** (`ESC[38;2;215;119;87m`, confirmed in `spike/pty/claude-tui-capture.txt`). This is the fact that decides the emulator library (§4).

## 2. Interfaces that M2/M3 sit behind (decision 9)

Define these in M1 with M1-only implementations, so later milestones are additive.

```go
// internal/clock
type Clock interface {
    Now() time.Time
    After(d time.Duration) <-chan time.Time
    NewTicker(d time.Duration) Ticker
}
type Ticker interface { C() <-chan time.Time; Stop() }
```
Injected into: `store.Open` (all `*_at_ms` columns come from the Clock, making DB assertions deterministic), `supervisor.New` (spawn timestamps, shutdown grace deadline, attach ping/pong timers), `daemon.New` (uptime). **Never call `time.Now()` outside `clock/`** — enforce with a `go vet`-adjacent grep in CI.

```go
// internal/state — M2 owns this
type Engine interface {
    // OnHookEvent is M2's entry point; M1 never calls it.
    OnHookEvent(ctx context.Context, sessionID string, ev HookEvent) error
    // OnLifecycle is called by the supervisor for every spawn/exit/attach/detach in M1.
    OnLifecycle(ctx context.Context, sessionID string, kind session.EventKind, data any) error
    // State is what `corral ls` renders. M1's NoopEngine derives it purely from
    // session.Status; M2 overrides with hook-driven Working/Blocked/Idle.
    State(sessionID string) session.AgentState
}
type NoopEngine struct{ store *store.Store }
```
The supervisor calls `Engine.OnLifecycle` for every transition (which is also where the `events` row is written) so M2 only swaps the implementation.

```go
// internal/checkpoint — M3 owns this
type Checkpointer interface {
    // Checkpoint durably records enough to bring the session back later,
    // then stops the live process. M3 adds flush-verified turn-boundary waiting.
    Checkpoint(ctx context.Context, s *supervisor.LiveSession, reason string) (Token, error)
    // Restore relaunches from a Token. M1: `claude --resume <id>`.
    Restore(ctx context.Context, rec session.Session) (session.Spec, error)
    // Resumable reports whether Restore can succeed.
    Resumable(rec session.Session) (bool, string)
}
type Token struct { ClaudeSessionID string; TurnBoundaryVerified bool; At time.Time }
```
**M1's whole restart strategy is `ResumeCheckpointer`** — `Checkpoint` = SIGTERM-pgroup/grace/SIGKILL + persist `claude_session_id`, `TurnBoundaryVerified: false`; `Restore` = build a Spec with `--resume`. M3 replaces the body, not the callers. This is the single most important structural decision in the file after §3.

Also seam-only, no interface needed yet: `session.Mode` already has a `ModeHeadless` constant that M4 fills in; `supervisor.Spawn` switches on it and returns `ErrUnsupportedMode` in M1.

## 3. Daemon lifecycle

### 3.1 Daemonization
Two-hop setsid re-exec, exactly as proven in the spike:
`corral daemon` (launcher) → `exec.Command(self, "daemon-run", ...)` with `SysProcAttr{Setsid: true}`, stdin `/dev/null`, stdout/stderr → `<state_dir>/daemon.log`, `ExtraFiles: []*os.File{readyW}` (fd 3). Launcher waits ≤10s for a single line on the ready pipe (`OK` / `ERR: <msg>`), prints `daemon started pid=… sock=…`, `child.Process.Release()`, exits. `corral daemon --foreground` skips the re-exec (debugging only; not the tested path).

`daemon-run` self-checks `syscall.Getsid(0) == os.Getpid()` and logs at WARN if not — a silently-failed setsid degrades to "works until the terminal closes," which is exactly the bug class worth a one-line assertion.

### 3.2 Startup sequence (`daemon-run`), in order
1. Load daemon config (defaults ← user TOML ← env). Init `slog` handler per `log_format`/`log_level` to `daemon.log`.
2. setsid self-check (above).
3. `MkdirAll(state_dir, 0700)`; `Chmod` it to 0700 unconditionally (fixes a pre-existing loose dir).
4. **Acquire singleton:** `flock(<state_dir>/daemon.lock, LOCK_EX|LOCK_NB)`. Failure → `ERR: another corral daemon holds the lock`. **The flock is the mutual-exclusion primitive; the PID file is advisory only and must never be consulted for liveness.**
5. Open store; run migrations inside the flock; log `schema_version`.
6. Freeze the child-env snapshot (§7.2): capture the whitelisted names from the *daemon's own* environment once, here. Log the captured key names at DEBUG.
7. Resolve `claude_bin` (absolute path, or `exec.LookPath`); best-effort `claude --version` with a 3s timeout, logged, non-fatal.
8. **Recovery** (§3.5). Runs before the socket is up, so no client can observe a half-recovered world.
9. **Acquire socket** (§3.3), `Chmod(sock, 0600)`, write `daemon.pid` (0600).
10. Start `http.Server` on the unix listener. Write `OK\n` to the ready fd, close it.
11. Block on the signal/shutdown select.

### 3.3 Socket acquisition / stale sockets
Inside the flock:
```
listen := net.Listen("unix", path)
if errors.Is(err, syscall.EADDRINUSE) || os.IsExist(err):
    if c, derr := net.DialTimeout("unix", path, 500ms); derr == nil:
        // Someone is listening even though we hold the flock — refuse loudly.
        // (Means the flock file was deleted out from under a live daemon.)
        return fmt.Errorf("socket %s is live but lock is free; refusing to start", path)
    os.Remove(path)                 // stale
    listen = net.Listen("unix", path)  // retry once, no further retries
```
Because the flock is already held, "is this socket stale?" is decidable without racing another starting daemon. Dial-probe first anyway, because deleting a live socket is unrecoverable.

### 3.4 Signals
| Signal | Behavior |
|---|---|
| SIGTERM, SIGINT | graceful shutdown (§3.6) |
| second SIGTERM/SIGINT while draining | log, `KillGroup(SIGKILL)` every tracked pgid, `os.Exit(1)` |
| SIGHUP | re-read the **user** config file; apply `log_level` only. Everything else logged as "ignored on reload." |
| SIGPIPE | Go default (ignored on non-stdio fds) |
| SIGCHLD | unused — one `cmd.Wait()` goroutine per session |

### 3.5 Recovery on startup (the daemon-restart path)
```
for rec in store.SessionsWhere(desired_state = 'running'):
    if rec.PID != 0 && procinfo.Alive(rec.PID, rec.ProcStartNs):
        // The PTY master died with the previous daemon; the fd is unrecoverable.
        // Re-adoption is impossible, so reap deterministically.
        log.Warn("orphaned child from previous daemon; reaping", pid, pgid)
        procinfo.KillGroup(rec.PGID, SIGTERM); wait shutdown_grace; KillGroup(rec.PGID, SIGKILL)
        emit session.orphan_reaped
    ok, why := checkpointer.Resumable(rec)
    if !ok:  rec.Status = failed; rec.DesiredState = stopped; emit session.unresumable{why}; continue
    spec := checkpointer.Restore(rec)     // argv gains --resume <claude_session_id>
    supervisor.Spawn(spec)                 // resume_count++, emit session.resumed
```
`procinfo.KillGroup` **refuses** if `pgid <= 1`, if `pgid == syscall.Getpgrp()`, or if `pgid` was not recorded by corral. Never match processes by name (the spike's explicit warning — this machine runs unrelated `claude` processes).

Recovery is fully driven by `desired_state` (durable intent) versus `status` (last observed reality). This split is the load-bearing schema decision.

### 3.6 Shutdown sequence
1. Enter `draining`; `ln.Close()` (stop accepting).
2. For each attached client: send `Error{code:"daemon_shutdown"}`, then close. Clients print `[daemon shutting down]` and exit 0.
3. For each live session, concurrently: `checkpointer.Checkpoint(s, "daemon_shutdown")` → `status='stopping'` → `KillGroup(pgid, SIGTERM)` → wait ≤ `shutdown_grace` (Clock) → `KillGroup(pgid, SIGKILL)`; record `exit_code`/`exit_signal`, set `status='exited'`, **leave `desired_state='running'`**.
4. Wait for all output-log/screen goroutines; close output logs.
5. `PRAGMA wal_checkpoint(TRUNCATE)`; close DB.
6. Remove socket + pid file; release flock; exit 0.

### 3.7 Decision 2 — rejected alternatives

**Rejected: per-session PTY-holder process** (a tiny setsid'd `corral session-host` owning the PTY master + emulator, reachable over its own socket, so daemon restart re-adopts a live child with zero conversation loss). It is technically the strongest answer and it is what dtach/abduco do. Rejected because it contradicts corral's stated architecture and positioning: RUNBOOK §2 decision 4 says *"Daemon restart = re-read SQLite, resume what was running. Nothing depends on the process staying alive,"* and §1 sells corral's persistence model explicitly **against** Herdr's "live PTY processes on server." A holder process also does not survive machine reboot (which `--resume` does), doubles the binary roles, adds a second protocol and a second lifecycle to reap, and moves the screen state out of the daemon so `corral ls` needs an RPC to render anything. If a future milestone needs zero-loss daemon upgrades, the correct move is M3's flush-verified checkpointing plus a `checkpoint-all → swap → resume-all` sequence (§10 already specifies that path), not a holder process.

**Rejected: in-process re-adoption of live children.** Not implementable — the PTY master fd dies with the daemon and there is no fd to recover. Enumerated only so the executor stops looking for a trick.

**Accepted cost, documented:** a daemon restart while a session is mid-turn loses that turn (M0 finding #1: SIGKILL between "user message sent" and post-turn flush loses the whole turn, cleanly). M1 cannot detect turn boundaries (no hooks, no stream parsing), so this is a known M1 limitation, mitigated only by preferring SIGTERM + a 5s grace. Whether SIGTERM is actually lossless is verification V3 (§11 step 0).

## 4. Headless terminal emulator (decision 3)

### Library: `github.com/charmbracelet/x/vt`, pinned to an exact pseudo-version.

Evaluated:
- **`hinshun/vt10x`** — rejected. Its `Glyph.FG/BG` is `Color uint32` covering ANSI-16 and xterm-256 only. `claude`'s TUI is 24-bit truecolor (`ESC[38;2;215;119;87m` appears throughout `spike/pty/claude-tui-capture.txt`); vt10x would silently flatten every color in the repaint. It also has no bracketed-paste mode in its `ModeFlag` set, and it has been frozen since March 2022.
- **`charmbracelet/x/vt`** — chosen. Truecolor cells via `uv.Cell`/`uv.Style`; `Render() string` produces a styled snapshot already encoded as ANSI; `IsAltScreen()`; `Resize(w,h)`; `Cursor()` with position/visibility/style; `Callbacks{AltScreen, CursorVisibility, EnableMode, DisableMode, Title, …}`; and — decisively — `Emulator.Read()` **generates the device-query replies** (CPR/DA/etc.), which lets corral answer a child's `ESC[6n` even with nobody attached. The spike explicitly flagged unanswered queries as an unknown; this closes it.
- **`gitpod-io/xterm-go`** — not chosen; more spec-complete on paper, but heavier and no ANSI-render path, so we'd hand-roll the painter anyway.

**Risk acknowledgement (write an ADR: `docs/adr/0002-terminal-emulator.md`):** `x/vt` has no tagged release and its module ships as a pseudo-version alongside untagged `charmbracelet/ultraviolet`. Pin the exact pseudo-version in `go.mod`; upgrades are a deliberate, manual act. The grid-equivalence test (§10.2) is the regression harness that makes those bumps safe — it is the reason the risk is acceptable.

### The per-session component

```go
// internal/screen
type Screen struct { /* mu, *vt.Emulator, modeSet, cursorVisible, title, subs, log */ }

func New(rows, cols int, log *slog.Logger) *Screen

// Feed is called ONLY by the single PTY-reader goroutine.
func (s *Screen) Feed(p []byte)

// Snapshot returns a byte sequence that, applied to a fresh terminal,
// reproduces the current visual state, AND atomically registers sub for
// subsequent live bytes. No byte can be lost or duplicated across the seam.
func (s *Screen) Attach(sub *Subscriber) (repaint []byte)
func (s *Screen) Detach(sub *Subscriber)

func (s *Screen) Resize(rows, cols int)
func (s *Screen) Size() (rows, cols int)
func (s *Screen) Replies() io.Reader   // emu.Read(): device-query answers → PTY master
func (s *Screen) DebugGrid() Grid      // test-only: cells+styles+cursor+modes, comparable
```

`Feed` does, under `s.mu`: (1) `modes.Sniff(p)` — an independent scanner for `CSI ? <params> h|l` recording a last-write-wins `map[int]bool`, tolerating the multi-param `CSI ?1000;1002h` form; (2) `emu.Write(p)`; (3) `outputlog.Write(p)`; (4) non-blocking hand-off to each subscriber (§5.4).

**Why an independent mode sniffer rather than only `Callbacks.EnableMode/DisableMode`:** `x/vt` does not recognize DEC private mode **2031**, which `claude` sets on startup (confirmed in the capture: `ESC[?2031h`). Callbacks would silently drop it. The sniffer is ~40 lines, library-independent, and future-proof against whatever private mode claude adopts next. Keep both: callbacks feed alt-screen/cursor-visibility, the sniffer owns the private-mode set.

### Repaint sequence (`snapshot.go`), emitted in this exact order
1. `ESC[?1049h` if alt-screen is active (else nothing — the client is already on the primary screen).
2. `ESC[2J ESC[H` — clear and home.
3. All sniffed private modes, re-emitted as `ESC[?<n>h` / `ESC[?<n>l`, **excluding** 1049 (already handled) and 25 (deferred to step 6). In practice for claude: `?1000h ?1002h ?1003h ?1006h ?2004h ?1004h ?2031h`.
4. `ESC]0;<title>BEL` if a title was seen.
5. `emu.Render()` — the styled grid. Wrap: emit `ESC[<row>;1H` before each line so a stale client cursor cannot shift the paint, and always `ESC[0m` at the end of each line.
6. `ESC[<cy+1>;<cx+1>H`, then `ESC[?25h` or `ESC[?25l` per current cursor visibility (claude sends `?25l`).

Start with `Render()`. If the grid-equivalence test (§10.2) shows it loses information, replace step 5 with a hand-rolled `CellAt` painter — that test, not intuition, is the arbiter.

**Live phase after attach is raw pass-through.** Once the client's terminal is in sync with the grid, streaming raw PTY bytes is correct and cheap; the emulator keeps consuming in parallel purely to stay authoritative for the *next* attach. This is the whole reattach design in one sentence.

### Device-query replies: known duplicate
A goroutine pumps `screen.Replies()` → PTY master, always, attached or not. When a client *is* attached, the child's raw query also reaches the real terminal, which replies, and the client forwards it as an `Input` frame — so the child receives **two** answers to e.g. `ESC[6n`. **Decision for M1: accept the duplicate.** Rationale: the emulator's reported identity stays stable across attach/detach (the alternative — answering only while detached — makes the child's view of its terminal change on every attach), and applications are tolerant of a duplicate CPR. Document it in known limitations; revisit if a real TUI misbehaves.

## 5. Attach protocol (decision 4)

### 5.1 Transport: HTTP upgrade on the same unix socket
`GET /v1/sessions/{id}/attach` with `Upgrade: corral-attach/1` + `Connection: Upgrade`. The handler validates, replies `101 Switching Protocols`, then `http.Hijacker` (via `http.NewResponseController(w).Hijack()`) yields the raw `net.Conn`. One socket, one listener, one server, one version-handshake middleware. Client SDK exposes `client.Attach(ctx, id) (net.Conn, error)`.

### 5.2 Framing
`[1 byte type][4 byte big-endian length][payload]`. Max payload 1 MiB; oversize is a protocol error (close). **Rule: control frames carry JSON, data frames carry raw bytes.** Frame types are stable forever; new control frames get new type bytes, new JSON fields are additive-optional. No framing version negotiation — that lives in the HTTP layer.

| Type | Name | Dir | Payload |
|---|---|---|---|
| `0x01` | Hello | C→D | `{"rows":40,"cols":120,"take_over":true,"client_version":"0.1.0"}` |
| `0x02` | Input | C→D | raw bytes → PTY master |
| `0x03` | Resize | C→D | `{"rows":40,"cols":120}` |
| `0x04` | Goodbye | C→D | `{"reason":"detach"}` — the clean-detach signal |
| `0x05` | Ping | both | `{"n":7}` |
| `0x06` | Pong | both | `{"n":7}` |
| `0x81` | Ready | D→C | `{"session_id","name","rows","cols","alt_screen":true,"repaint_bytes":8123}` |
| `0x82` | Output | D→C | raw bytes (repaint first, then live) |
| `0x83` | Exit | D→C | `{"exit_code":0,"signal":"","reason":"child_exited"}` |
| `0x84` | Error | D→C | `{"code":"already_attached","message":"…"}` |
| `0x85` | Goodbye | D→C | `{"reason":"detach_ack"}` |
| `0x86` | Detached | D→C | `{"reason":"taken_over"}` |

Sequence: client sends `Hello` → daemon sends `Ready`, then `Output` frames containing the repaint, then live `Output`. Detach: client sends `Goodbye{detach}`, waits ≤2s for `Goodbye{detach_ack}`, closes, restores its terminal. **Missing goodbye = crash, not detach** — the daemon records `session.client_crashed` instead of `session.detached`, which is precisely what spike finding #5 asked for.

**Ping/pong completes the detach-vs-crash story.** The daemon pings every `attach.ping_interval` (15s) using the Clock; no `Pong` within `attach.ping_timeout` (45s) → treat as crash-disconnect and drop the attachment. This catches the case a closed socket does not: a client that is SIGSTOP'd or on a wedged network.

### 5.3 Detach key
tmux-style prefix, **not** a bare control byte (finding #5: bare bytes collide with app keybindings). Default `attach.prefix_key = "C-\\"` (0x1c — the spike verified neither bash, vi, nor claude binds it), `attach.detach_key = "d"`. Client-side state machine, entirely local:
- byte == prefix and not pending → swallow, set pending, do not forward.
- pending and byte == detach_key → send `Goodbye{detach}`, exit.
- pending and byte == prefix → forward one literal prefix byte (escape hatch).
- pending and anything else → forward prefix byte then that byte.
- Pending state expires on the next read regardless (no timeout needed).

### 5.4 Backpressure — do not port the spike's bug
The spike's `scrollback.Feed` wrote to the live client **inline under the buffer mutex**. If an attached client stops reading, the PTY reader blocks, the PTY buffer fills, and **the child blocks on output** — violating §5.4's "the daemon never misbehaves because of what the agent does," in reverse.

M1 design: each attachment is a `Subscriber{ch chan []byte /* cap 256 */, done chan struct{} }` with its own writer goroutine draining `ch` to the socket. `Screen.Feed` does a `select { case ch <- buf: default: markOverflow() }` — **never blocks**. On overflow: send `Error{code:"client_too_slow"}`, close the attachment, emit `session.client_dropped`. This is safe precisely because the grid is authoritative: the dropped client's next attach re-snapshots from the grid with zero information loss. Buffers handed to `ch` must be copies (the PTY read buffer is reused).

### 5.5 One attacher
At most one attached client per session. `Hello{take_over:true}` (the CLI default) kicks the incumbent with `Detached{taken_over}`; `take_over:false` gets `Error{code:"already_attached"}`. **Multi-attach shared view is explicitly out of M1 scope** — do not build it speculatively.

## 6. Store (decision 5)

### 6.1 Migration mechanism
**Embedded SQL files + a ~60-line runner.** No migration library.
- `//go:embed migrations/*.sql` → `fs.FS`. Files named `NNNN_slug.sql`, lexically ordered.
- Version tracked in `PRAGMA user_version` (integer == highest applied file number). No extra table, no bootstrapping problem.
- Runner: read current `user_version`; for each file with `N > current`, in one transaction per file: exec the file, `PRAGMA user_version = N`. Any error → rollback that file's transaction and return; the DB stays at the last good version.
- Runner takes an `fs.FS` parameter so tests can inject synthetic migration sets.
- Downgrades are unsupported: `user_version > len(migrations)` → refuse to open with `ErrSchemaTooNew` ("this DB was written by a newer corral").

### 6.2 DDL — `migrations/0001_init.sql`
```sql
PRAGMA foreign_keys = ON;

CREATE TABLE sessions (
  id                  TEXT    PRIMARY KEY,        -- uuidv4; also passed as claude --session-id
  name                TEXT    NOT NULL UNIQUE,    -- human handle used by CLI
  mode                TEXT    NOT NULL,           -- 'interactive' (M1); 'headless' later
  cwd                 TEXT    NOT NULL,
  claude_bin          TEXT    NOT NULL,           -- resolved absolute path actually executed

  argv_json           TEXT    NOT NULL,           -- exact argv used, JSON array
  env_keys_json       TEXT    NOT NULL,           -- child env KEY NAMES only, JSON array (never values)
  settings_path       TEXT    NOT NULL,           -- pinned --settings file

  rows                INTEGER NOT NULL,
  cols                INTEGER NOT NULL,
  exit_code           INTEGER,
  exit_signal         TEXT,
  resume_count        INTEGER NOT NULL DEFAULT 0,
```

`env_keys_json` stores **names only, never values** — §7 forbids persisting secrets, and `ANTHROPIC_API_KEY` is in the whitelist.

### 6.3 Connection settings
`modernc.org/sqlite`, DSN `file:<path>?_pragma=busy_timeout(5000)&_pragma=journal_mode(WAL)&_pragma=synchronous(NORMAL)&_pragma=foreign_keys(ON)`. `db.SetMaxOpenConns(1)` — one connection, all access serialized, zero locking questions and zero `SQLITE_BUSY` in a single-daemon world. Revisit only if profiling demands it. DB file and `-wal`/`-shm` chmod 0600 after open.

### 6.4 Persisted vs derived
**Persisted:** everything in the DDL above. **Derived, never persisted:** the screen grid and private-mode set, the PTY master fd, live output buffers, whether a client is currently attached, daemon uptime, `AgentState` as rendered by `corral ls`. A resumed session starts with a **blank grid** — claude repaints its whole TUI on startup, so this is correct and requires no screen serialization.

## 7. Session spawn spec (decision 6)

### 7.1 The spec
```go
// internal/session
type Mode string; const (ModeInteractive Mode = "interactive"; ModeHeadless Mode = "headless")

type Spec struct {
    ID              string            // uuidv4, generated by corral; == claude --session-id on first spawn
    Name            string            // unique handle; default "<basename(cwd)>-<n>"
    Mode            Mode
    Cwd             string            // absolute, must exist and be a directory
    ClaudeBin       string            // absolute, resolved via LookPath if needed
    Model           string            // "" = omit --model
    SettingSources  string            // value for --setting-sources
    SettingsPath    string            // pinned settings file (written before spawn)
    ExtraArgs       []string          // reserved; empty in M1
    Env             map[string]string // the complete child environment. Nothing else is inherited.
    Rows, Cols      uint16            // initial PTY size (default 40x120 when nothing is attached)
    ResumeFrom      string            // "" = fresh (--session-id); else --resume <this>
}
```

### 7.2 Environment: nothing is inherited unless explicitly named
`Env` is constructed, never `os.Environ()`-derived (finding #3: `CLAUDE_CODE_CHILD_SESSION` leaked in and visibly changed the child's behavior). Because the whitelist is a strict allowlist, **no denylist is needed by construction.**

Copied from the frozen daemon-start snapshot if present:
`HOME, USER, LOGNAME, SHELL, PATH, TMPDIR, LANG, LC_ALL, LC_CTYPE, TZ, SSH_AUTH_SOCK, ANTHROPIC_API_KEY, ANTHROPIC_AUTH_TOKEN, ANTHROPIC_BASE_URL`
plus any name listed in `session.env_passthrough` (user config / env only — see §8 trust boundary).

Set by corral unconditionally:
`TERM` (from config, default `xterm-256color`), `COLORTERM=truecolor`, `PWD=<Spec.Cwd>`, `CORRAL_SESSION_ID=<Spec.ID>`, `CORRAL_SOCK=<socket path>`.

Reserved for M2, not set in M1: `CORRAL_SESSION_SECRET`.

Note the frozen-snapshot rule: the whitelist is read from the daemon's environment **once, at daemon startup**, not at spawn time. Spawn behavior is then a pure function of config + snapshot, which is what makes it testable.

### 7.3 argv
```
<claude_bin>
  --session-id <ID>            (fresh spawn)   |   --resume <ResumeFrom>   (restore)
  --settings <SettingsPath>
  --setting-sources <SettingSources>
  --name <Name>
  [--model <Model>]            (omitted when empty)
```
No `-p`, no `--output-format` — M1 is interactive TUI only. Spawn via `pty.StartWithSize(cmd, &pty.Winsize{Rows, Cols})`, which already sets `Setsid: true, Setctty: true` for the child; record `pid`, `pgid` (== pid, since the child is a session leader), and `proc_start_ns` from `procinfo.StartTime(pid)` immediately.

### 7.4 Pinned settings mechanics
Per-session directory `<state_dir>/sessions/<ID>/`, mode 0700:
- **`settings.json`** (0600) — passed as `--settings`. **M1 content is exactly `{"hooks": {}}`.**
- **`meta.json`** (0600) — corral's own provenance: `{"corral_version","api_version",​"session_id","name","created_at","spec_hash"}`. Never passed to claude.
- **`output.log`** (0600) — size-capped raw PTY tee (`session.output_log_max_bytes`, default 8 MiB; stop writing and log one warning at the cap, no rotation). **Diagnostics only — never replayed to a client.** This is also the seed of M3's authoritative stdout tee.

**Why provenance lives in a sibling file and not inside `settings.json`:** `claude --help` states that in non-interactive mode *"settings files that fail validation are silently ignored (no error dialog is shown)."* A custom `$corral` key risks silently disabling the entire pinned file — the exact failure mode that finding #3 says we must eliminate. `settings.json` therefore contains **only** documented Claude Code settings keys. `{"hooks": {}}` is valid, inert, and is precisely the shape M2 fills in, so M2 changes one function body and nothing else.

**Why `setting_sources` defaults to the permissive `"user,project,local"`:** dropping `user` would also drop `apiKeyHelper` and break auth for a real class of users. The pinned `--settings` file is *additional* and highest-precedence, which is what actually satisfies finding #3. Users who want full isolation set `session.setting_sources = "project,local"`. Passing the flag explicitly (rather than relying on the default) makes the choice visible in `argv_json` and in `corral config`. **This depends on verification V2 (§11 step 0)** — if `--settings` does not in fact win over user settings, the default must change to `"project,local"` and the limitation documented.

## 8. Config (decision 7)

### 8.1 Two scopes — a structural decision, not a detail
- **Daemon scope** (`socket`, `state_dir`, `log_level`, `log_format`, `shutdown_grace`): resolved once at daemon startup. Sources: **defaults → `~/.corral/config.toml` → env**. A repo file can never change daemon-global behavior.
- **Session scope** (`claude_bin`, `model`, `setting_sources`, `env_passthrough`, `scrollback_lines`, `term`, `output_log_max_bytes`) and **attach scope** (`prefix_key`, `detach_key`, `ping_interval`, `ping_timeout`): resolved **per session, from the session's cwd**, at `corral new` time, by the daemon. Sources: **defaults → `~/.corral/config.toml` → nearest `.corral.toml` walking up from cwd to the git root (or filesystem root, whichever comes first) → env → API request fields**.

Attach-scope keys are resolved *client*-side for `prefix_key`/`detach_key` (the detach state machine is local) and *daemon*-side for ping timings.

### 8.2 Repo-file trust boundary
A repo's `.corral.toml` is attacker-controlled content in any cloned repository, and the daemon executes a binary path from session config. **Repo files may set only: `session.model`, `session.scrollback_lines`, `session.term`.** Every other key in a repo file is ignored with a WARN log naming the file and key. In particular `session.claude_bin`, `session.env_passthrough`, `session.setting_sources`, and the entire `[daemon]` and `[attach]` tables are **user-file/env only**. Enforced by a single allowlist in `internal/config/repo_allowlist.go` and covered by a security test (§7 "applies from M1, not bolted on later").

### 8.3 Implementation
Layer structs with pointer fields; decode each source into its own layer with `BurntSushi/toml`; merge in precedence order with a hand-written `merge(dst, src *layer, source string)` that records `Sources[key] = source` for every field it actually overwrites. No reflection, no struct tags magic — ~120 lines, trivially unit-testable, and `corral config` falls out for free.

Env rule, exactly one form: `CORRAL_<SECTION>_<KEY>`, uppercased, `.`→`_`. e.g. `CORRAL_DAEMON_SOCKET`, `CORRAL_SESSION_MODEL`, `CORRAL_ATTACH_PREFIX_KEY`. No aliases.

### 8.4 M1 config keys (complete)
```toml
[daemon]
socket                = "~/.corral/corral.sock"
state_dir             = "~/.corral"
log_level             = "info"                # debug|info|warn|error
log_format            = "text"                # text|json
shutdown_grace        = "5s"

[session]
claude_bin            = "claude"              # PATH-resolved unless absolute
model                 = ""                    # "" = claude default (--model omitted)
setting_sources       = "user,project,local"
env_passthrough       = []                    # extra env var NAMES added to the whitelist
term                  = "xterm-256color"
scrollback_lines      = 2000
output_log_max_bytes  = "8MiB"

[attach]
prefix_key            = "C-\\"
detach_key            = "d"
ping_interval         = "15s"
ping_timeout          = "45s"
```
`~` expands to `$HOME`. Durations parse via `time.ParseDuration`; byte sizes via a small `ParseBytes` in `config/`.

`corral config [--cwd DIR]` prints `section.key = value   # from <default|~/.corral/config.toml|/path/.corral.toml|env CORRAL_X|request>`, and prints `# ignored (repo files may not set this key)` lines for rejected repo keys.

## 9. API surface (decision 8)

All endpoints under `/v1/`. Content type `application/json`. Error envelope on every non-2xx:
```json
{"error":{"code":"session_not_found","message":"no session named \"api-refactor\"","details":{}}}
```
Codes: `bad_request`, `version_mismatch`, `session_not_found`, `session_name_taken`, `already_attached`, `client_too_slow`, `unsupported_mode`, `daemon_shutting_down`, `internal`.

### 9.1 Version handshake
Every client request sends `Corral-Api-Version: 1` and `Corral-Client-Version: <semver>`. Middleware: missing or non-integer → `400 version_mismatch`; integer ≠ 1 → `400 version_mismatch` with a message naming both versions. Every response carries `Corral-Api-Version: 1` and `Corral-Daemon-Version: <semver>`; the client compares `Corral-Daemon-Version` against its own build and prints a one-line stderr warning on mismatch (never fails). A `404` on any `/v1/...` path makes the client print "daemon speaks a different API version — restart it (`corral daemon` after `kill <pid>`)". **No pre-flight round trip.**

### 9.2 Endpoints
| Method | Path | Request | Response |
|---|---|---|---|
| GET | `/v1/version` | — | `{"daemon_version","api_version":1,"schema_version":1,"pid","started_at","uptime_ms"}` |
| GET | `/v1/config?cwd=…` | — | `{"values":{"session.model":"…"},"sources":{"session.model":"env CORRAL_SESSION_MODEL"},"ignored":[{"file":"…","key":"…"}]}` |
| GET | `/v1/sessions` | — | `{"sessions":[<Session>]}` |
| POST | `/v1/sessions` | `{"name":"api-refactor","cwd":"/abs/path","mode":"interactive","model":"","rows":40,"cols":120}` | `201` + `<Session>` |
| GET | `/v1/sessions/{idOrName}` | — | `<Session>` |
| DELETE | `/v1/sessions/{idOrName}` | `?grace=5s` | `200` + `<Session>` (post-kill) |
| GET | `/v1/sessions/{idOrName}/attach` | `Upgrade: corral-attach/1` | `101` then frames (§5) |
| POST | `/v1/daemon/shutdown` | `{"grace":"5s"}` | `202 {"accepted":true}` then the daemon drains |

`<Session>` JSON (derived from the DDL, plus derived fields):
```json
{
  "id":"3f1c…","name":"api-refactor","mode":"interactive","cwd":"/Users/d/code/x",
  "status":"running","desired_state":"running","agent_state":"running",
  "attached":true,"pid":81234,"model":"","claude_session_id":"3f1c…",
  "rows":40,"cols":120,"resume_count":1,
  "created_at":"2026-08-07T…","started_at":"…","last_attached_at":"…",
  "ended_at":null,"exit_code":null,"exit_signal":null
}
```
`agent_state` is `state.Engine.State()` output — in M1 always derived from `status` (`starting|running|exited|failed`); M2 replaces it with `working|blocked(reason)|idle` without an API shape change. **This field exists in M1 precisely so M2 is not a breaking change.**

`corral ls` renders `NAME  STATE  ATTACHED  CWD  UPTIME  PID`; `--json` prints the raw array.

`corral new` resolves `--cwd` (default `$PWD`) to an absolute path client-side, sends it, then — unless `--no-attach` — immediately attaches. `corral kill <name>` sets `desired_state='stopped'` **before** signalling, so a daemon crash mid-kill does not resurrect the session on restart.

2. **`TestClientCrashIsNotDetach`** — attach, then close the socket without a `Goodbye`; assert the `events` table has `session.client_crashed` and **not** `session.detached`, and the session is still `running`.
3. **`TestSlowClientIsDropped`** — attach and never read; make fakeclaude emit a large burst; assert the client gets `Error{client_too_slow}`, the session stays `running`, **and the child was never blocked** (fakeclaude timestamps its writes; assert no stall > 1s).
4. **`TestTakeOver`** — two attaches; incumbent receives `Detached{taken_over}`; `take_over:false` gets `Error{already_attached}`.
5. **`TestResizePropagates`** — send `Resize`, assert fakeclaude re-renders at the new width (its banner width is deterministic) and `sessions.cols` is updated.
6. **`TestGracefulRestartResumes`** (the headline test) — create session S, attach, type two prompts (so the fake transcript has content), detach. `POST /v1/daemon/shutdown`; poll until the daemon pid is gone; assert the fakeclaude child is gone and the DB row is `desired_state:"running", status:"exited"`. Start the daemon again on the same `state_dir`; poll `GET /v1/sessions/S` until `status:"running"`. Then assert:
   - `resume_count == 1` and an event `session.resumed` exists;
   - `invocation-2.json` argv contains `--resume S` and **not** `--session-id`;
   - `invocation-2.json` environ has no `CLAUDE_*` key and exactly the expected whitelist keys;
   - reattaching yields a repaint that **begins with `ESC[?1049h`** and **contains both earlier prompts** — the precise assertion that raw-byte replay would fail.
7. **`TestCrashRestartReapsAndResumes`** — `SIGKILL` the daemon pid. Then (a) if the child is still alive, assert the next startup emits `session.orphan_reaped` and the child is gone afterwards; (b) either way, assert the session ends up `running` with `resume_count == 1`. Written to pass on **both** branches, because child survival under daemon SIGKILL is unverified (§0).
8. **`TestGraceEscalation`** — `CORRAL_FAKE_IGNORE_SIGTERM=1`, `DELETE ?grace=300ms`; assert the child is SIGKILLed and `exit_signal == "SIGKILL"`.
9. **`TestChildExitIsObserved`** — `CORRAL_FAKE_EXIT_AFTER=200ms CORRAL_FAKE_EXIT_CODE=3`; assert an attached client receives `Exit{exit_code:3}`, `status:"exited"`, `desired_state:"stopped"` (a self-exited child is not resurrected), and event `session.exited`.
10. **`TestStaleSocket`** — `SIGKILL` the daemon (leaving `corral.sock` and `daemon.lock` on disk), restart, assert startup succeeds and logs `removed stale socket`. Plus **`TestSecondDaemonRefused`**: a second `corral daemon` on the same `state_dir` exits non-zero with a message naming the lock.
11. **`TestVersionSkew`** — a hand-rolled request with `Corral-Api-Version: 2` gets `400 version_mismatch`.

**No `time.Sleep` for synchronization anywhere.** Integration waits use `waitFor(t, cond, timeout)` polling helpers or channel reads; unit timing uses `clocktest.FakeClock`. Per §5.4's flakiness policy, any test that flakes twice gets quarantined the same day.

## 12. Known limitations, documented in M1's README section

- **A daemon restart while a session is mid-turn loses that turn** (M0 finding #1). M1 cannot detect turn boundaries; M3's flush-verified checkpointing fixes it. Severity depends on verification V3.
- **Duplicate device-query replies while attached** (§4). Accepted for M1.
- **Workspace trust dialog.** Interactive mode has a real tty, so claude *may* show the trust prompt in a directory the user has not trusted. Corral does not attempt to fake or answer it — the emulator renders it faithfully and the session sits in `running` until a human attaches and answers. Decided rather than papered over: auto-answering a security prompt on the user's behalf is exactly the wrong instinct. fakeclaude never prompts, so integration tests are unaffected; this is real-claude-only. Trust the directory once by hand, or attach right after `corral new` (which is the CLI default).
- **launchd/keychain.** A daemon started by launchd at boot may not reach the login keychain, so OAuth-authed sessions can fail to authenticate. For M1, run the daemon from a logged-in user session, or provide `ANTHROPIC_API_KEY`. `corral service install` and a proper answer land with §10's packaging work.
- **Single attacher per session**; multi-attach shared view is out of scope.
- **Screen state is not persisted.** A resumed session repaints from claude's own startup render; pre-restart scrollback is gone (`output.log` keeps it for humans only).
- **`x/vt` is pinned to an untagged pseudo-version.** Upgrades are manual and gated on the grid-equivalence test.
