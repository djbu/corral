# corral M5 design — remote access + dashboard

**Milestone goal (RUNBOOK.md §M5):** an *opt-in* TCP listener (bearer
token + mandatory TLS), a minimal web dashboard (session list with live
states, blocked-reason answer cards, task-DAG view, SSE for live updates),
and a `corral --host` client flag that drives a remote daemon.
**Exit criterion (RUNBOOK.md §M5):** manage a session on a home server
from a phone browser.

M5 is the first milestone that opens a **network-facing surface**. Every
prior milestone's auth boundary was the unix socket's `0600` file
permission — the OS decided who could talk to the daemon. The moment a TCP
port is bound, that boundary is gone and corral must supply its own:
transport encryption (TLS) and caller authentication (bearer token). This
doc scopes the **v0.5.0 exit criterion** — a session driven and unblocked
from a phone browser — and, per m3/m4 deferral discipline (write it down,
don't lose it — §16), sequences everything the exit criterion does not
strictly require.

The governing security posture, non-negotiable and repeated from RUNBOOK
§7: **the unix socket stays the default and stays token-free (FS-perm
auth); TCP is opt-in, never bound unless the user explicitly configures a
`daemon.listen` address; TCP requires both TLS and a bearer token; tokens
are hashed at rest and never logged or returned after minting.**

## 0. What already exists (do not rebuild)

Grounding in the real tree (verified via source read, not memory):

- **The API server is transport-agnostic.** `api.Server` (`server.go:15`)
  is `{mux *http.ServeMux}`; `Handler()` returns
  `versionMiddleware(s.mux)` — a plain `http.Handler`. It has no idea
  whether it is served over a unix socket or TCP. This is the seam M5
  exploits: **auth is applied per-listener, wrapped around this same
  handler, so the mux and every handler stay transport-blind.** Do not
  teach handlers about tokens.
- **The version handshake is the middleware precedent.**
  `versionMiddleware` (`server.go:46`) sets `Corral-Api-Version` /
  `Corral-Daemon-Version` response headers on *every* response (including
  rejections) and rejects any request whose `Corral-Api-Version` header is
  missing/non-integer/mismatched with 400 before it reaches a handler. The
  bearer-auth middleware is the same shape, one layer out.
- **Constant-time secret comparison already exists and is done right.**
  `handlers_hooks.go:56-67`: hook deliveries authenticate against a
  per-session in-memory secret via `subtle.ConstantTimeCompare`, and the
  compare runs **even when the session is unknown** (`known == ""`) so the
  403's timing cannot distinguish "no such session" from "wrong secret";
  the response body is byte-identical in both cases; an
  `EventHookUnauthorized` durable event is appended on every failure.
  `CodeUnauthorized` already exists in `errors.go`. **The bearer
  middleware reuses this pattern verbatim** — it is the house style for
  auth, and it is correct. Do not invent a second comparison idiom.
- **The client SDK centralizes the wire contract.**
  `internal/api/client/client.go`: `Client{httpClient, sockPath, stderr}`,
  built by `New(sockPath, stderr)` with a unix-dialing `http.Transport`;
  `do(ctx, method, path, body)` sets the version headers and builds the
  URL as `"http://corral"+path`. **Every CLI subcommand goes through this
  package** (design doc §9), so `--host` is implemented *once* here, not
  per-command. Two things are hardcoded to unix today and must become
  fields: the dial target (`sockPath`) and the URL authority
  (`http://corral`). No `Authorization` header is ever set today.
- **The daemon binds exactly one listener.** `daemon.go:382-425`:
  `Listen(d.sockPath)` (unix) → `os.Chmod(sockPath, 0o600)` →
  `writePIDFile` → `srv := api.New()` + the `Register*` calls →
  `d.srv = &http.Server{Handler: srv.Handler()}` → `go d.srv.Serve(ln)`.
  `d.listener net.Listener` / `d.srv *http.Server` are single-valued
  fields. The TCP listener is an *additional* `tls.Listener` + a *second*
  `http.Server` serving the bearer-wrapped handler — the unix path is
  edited only to not assume it is the only listener at shutdown.
- **The repo-file trust boundary is enforced and total for `[daemon]`.**
  `config/repo_allowlist.go`: a repo's `.corral.toml` may set only
  `session.{model,scrollback_lines,term}`; **every** `daemon.*` key is
  individually rejected (`daemon.socket`, `daemon.state_dir`,
  `daemon.log_level`, …) with a `Rejection`. M5's new daemon keys
  (`daemon.listen`, `daemon.tls_cert`, `daemon.tls_key`) join that reject
  list — a cloned repo must never be able to open a network port or swap a
  cert. This is the m4-flagged "when a later step exposes new `[daemon]`
  config, that step MUST add it to the reject list" requirement (m4.md
  §8.3), now due.
- **Store migrations are `user_version`-gated, embedded, STRICT.** Latest
  is `0004_tasks.sql`. M5 adds `0005_api_tokens.sql`. Migration conn opens
  `foreign_keys(OFF)`; the long-lived conn is `foreign_keys(ON)`.
- **Blocked reasons are already structured and durable.**
  `state.BlockedReason` + the blocked/answer path (M2) exist: a session
  can be `blocked`, the reason is persisted, and `corral answer` unblocks
  it, its payload **never shell-interpolated** and gated three ways on the
  ntfy reply path. The dashboard's blocked-answer card is a **new
  presentation of an existing capability**, not new blocking machinery — it
  POSTs to the same answer path.
- **No SSE, no server-sent events, no event fan-out anywhere.**
  `grep -r "text/event-stream"` → nothing. Events are persisted to the
  `events` table (`AppendEvent`) and read back by polling (`corral run`
  polls `GET /v1/dags/{id}`; §11 m4). M5 adds the first *push* channel: a
  broker that fans persisted events out to live SSE subscribers.
- **No embedded static assets, no HTML anywhere.** `grep go:embed` →
  nothing served as a web page. The dashboard is greenfield, embedded via
  `//go:embed`, self-contained (no CDN — a home-server dashboard opened
  from a phone must work with no outbound internet from the browser).

**Absent — M5 adds:** `0005_api_tokens.sql` + token store methods; a token
mint/verify helper (`internal/apitoken`); a bearer-auth middleware
(`internal/api`); a self-signed TLS bootstrap
(`internal/tlsbootstrap`); an opt-in TCP+TLS listener in `daemon.go`; a
`baseURL`+`authToken` refactor of the client + `--host`/`--token` flags; an
SSE broker + `GET /v1/events/stream`; an embedded web dashboard;
`corral token {create,list,revoke}`; per-session scoped child tokens.

## 1. Scope: exit-criterion cut

The exit criterion — "manage a session on a home server from a phone
browser" — decomposes into exactly three capabilities, and they are
sequenced so each is independently testable before the next depends on it:

**In v0.5.0:**
1. **Authenticated network listener** — opt-in TCP, mandatory TLS
   (self-signed bootstrap), bearer token required. Tokens minted by
   `corral token create`, hashed at rest, verified constant-time. (steps
   26–30)
2. **Remote client** — `corral --host <addr> --token <tok>` drives a
   remote daemon; the client SDK gains a TLS+bearer transport. This is
   what makes the listener *usable* from another machine and is the CLI
   half of the exit criterion. (step 31)
3. **Web dashboard + live updates** — an embedded, self-contained web UI
   (session list with live states, blocked-reason answer cards, DAG view)
   fed by an SSE push channel. This is the *browser* half of the exit
   criterion. (steps 32–33)

**Deferred (with sequencing — §16):**
- **Per-session scoped child tokens** (agent-spawned-agent subtree
  confinement, RUNBOOK §7). The exit criterion is met by a single
  operator-scoped token; subtree confinement is a hardening step that
  matters once corral spawns agents that themselves call the API. Kept as
  **step 34** because the user scoped M5 as the full milestone, but it is
  the one piece severable to v0.5.1 if scope pressure hits — and the token
  schema is designed from step 26 to carry it, so severing it costs no
  migration. (§10)
- **Token rotation / expiry TTLs** — v0.5.0 tokens are revocable
  (`revoked_at`) but not auto-expiring. (§16)
- **mTLS / client certs**, **OIDC / SSO**, **CORS for third-party web
  origins** — the dashboard is same-origin, served by the daemon itself.
  (§16)
- **Multi-user / RBAC** — one operator, N tokens, all equally privileged
  (until step 34's scope column is enforced). (§16)

## 3. Token model + storage

### 3.1 Mint / hash / verify (`internal/apitoken`)

A token is a **256-bit random value**, `crypto/rand`, rendered as URL-safe
base64 with a short human prefix for greppability in a config file:
`crl_<43-char-base64>`. The prefix is cosmetic (helps a user recognize a
corral token in `~/.corral/config.toml`); it is part of the plaintext and
part of what is hashed.

- `Mint() (plaintext string, hash string, err error)` — reads 32 bytes
  from `crypto/rand`, encodes, prefixes, hashes.
- `Verify(plaintext, hash string) bool` — hashes `plaintext` and compares
  to `hash` with `subtle.ConstantTimeCompare`.

**Hash choice: SHA-256, not bcrypt/argon2.** Rationale, decided and
recorded: password hashes are deliberately slow to defend *low-entropy*
human secrets against offline brute force. An API token is a **256-bit
uniformly-random** value — there is no dictionary and no feasible brute
force regardless of hash speed, so a slow KDF buys nothing and adds a
per-request CPU cost on the hot path of *every authenticated request*. A
single SHA-256 is the correct primitive for high-entropy bearer tokens
(this is what GitHub/Stripe-style token systems do). The plaintext is
shown **once** at mint time and never again; only the hash is stored.

- **The plaintext is never persisted, never logged, never returned by any
  read endpoint.** `corral token create` prints it to stdout once; that is
  the only time it exists outside the operator's shell. This mirrors the
  per-session secret rule (in-memory only) extended to at-rest storage:
  what we store is un-reversible.

### 3.2 Schema (`0005_api_tokens.sql`, STRICT)

```sql
CREATE TABLE api_tokens (
    id           TEXT PRIMARY KEY,          -- uuid, safe to show/log (not the secret)
    token_hash   TEXT NOT NULL UNIQUE,      -- SHA-256 hex of the plaintext; the only stored form
    label        TEXT NOT NULL,             -- human label ("phone", "laptop"), for `token list`
    scope        TEXT NOT NULL DEFAULT 'admin', -- 'admin' | 'session' (step 34); admin = full
    session_id   TEXT,                      -- NULL for admin tokens; the subtree root for scope='session'
    created_ms   INTEGER NOT NULL,
    last_used_ms INTEGER,                   -- updated best-effort on verify (observability only)
    revoked_ms   INTEGER                    -- NULL = active; non-NULL = revoked, fails verify
) STRICT;
CREATE UNIQUE INDEX api_tokens_hash ON api_tokens(token_hash);
CREATE INDEX api_tokens_session ON api_tokens(session_id);
```

**Sharp edges:**
- `scope`/`session_id` exist **from step 26** even though enforcement
  lands in step 34 — so per-session tokens cost no migration to enable.
  Every token minted before step 34 is `scope='admin'`, `session_id=NULL`.
- `last_used_ms` is observability only; its write is best-effort and MUST
  NOT be on the critical path of auth (a failed update never fails a
  request). Decided: update it in a fire-and-forget goroutine after the
  request is authorized, never synchronously before `next.ServeHTTP`.
- **`token_hash` is the lookup key**, but verify still runs a
  constant-time compare after the indexed lookup (see §4) — the index is
  for the multi-token case, not a substitute for constant-time compare.

### 3.3 Store surface (`store/tokens.go`)

- `CreateToken(ctx, id, hash, label, scope string, sessionID *string) error`
- `VerifyToken(ctx, plaintext string) (TokenRow, bool, error)` — hashes
  plaintext, looks up by hash, returns the row iff active
  (`revoked_ms IS NULL`). Returns `(_, false, nil)` for
  no-match/revoked (not an error).
- `ListTokens(ctx) ([]TokenRow, error)` — returns id/label/scope/session/
  created/last_used/revoked. **Never returns `token_hash`** (it is not the
  plaintext, but there is no reason for it to leave the store, and keeping
  it in-store shrinks the blast radius of any read-path bug).
- `RevokeToken(ctx, id string) error` — sets `revoked_ms`; idempotent.
- `TouchToken(ctx, id string)` — best-effort `last_used_ms` update.

## 4. Bearer-auth middleware (`internal/api/middleware_auth.go`)

The middleware is the exact shape of `versionMiddleware`, one layer out,
and it reuses the hook-handler auth idiom (`handlers_hooks.go`) verbatim.

```go
type tokenVerifier interface {
    VerifyToken(ctx context.Context, plaintext string) (store.TokenRow, bool, error)
}

func bearerAuth(next http.Handler, v tokenVerifier, log *slog.Logger) http.Handler
```

Behavior:
- Extract the token from `Authorization: Bearer <token>`. Missing/
  malformed header ⇒ 401 `CodeUnauthorized`, body byte-identical to the
  wrong-token case.
- `VerifyToken`. **Even on a store miss, a constant-time compare against a
  fixed dummy hash runs** so the 401 timing cannot distinguish
  "no such token" from "revoked" from "malformed" — same discipline as
  `handlers_hooks.go:56-61`.
- On failure: append a durable `EventTokenUnauthorized` daemon-scoped event
  (session_id NULL) with **no token material** (not even a prefix — record
  the remote addr and the fact, never the secret), then 401.
- On success: stash the resolved `TokenRow` in the request context
  (`context.WithValue`) for step 34's scope check and for handlers that
  want the caller identity; fire-and-forget `TouchToken`; call
  `next.ServeHTTP`.

**Middleware ordering (decided): `bearerAuth(versionMiddleware(mux))`** —
auth is the **outermost** layer on the TCP handler. Rationale: an
unauthenticated remote caller should learn *nothing* about the daemon,
including whether its API version matches, before proving it holds a
token. The version headers are still emitted by `versionMiddleware` on the
authenticated inner path, so a *legitimate* remote client with a version
mismatch still gets the handshake headers. The unix handler is unchanged:
`versionMiddleware(mux)` with no auth layer.

**Server wiring (`server.go`):**
```go
func (s *Server) Handler() http.Handler                       // unix: versionMiddleware(mux) — unchanged
func (s *Server) AuthenticatedHandler(v tokenVerifier, log *slog.Logger) http.Handler // TCP: bearerAuth(versionMiddleware(mux))
```
The mux is shared; only the wrapping differs per listener. No route knows
which handler served it.

**Why the unix socket stays token-free (decided, load-bearing):** the unix
socket is `0600`, owned by the daemon's user; the OS already proves the
caller is that user. Requiring a token there would (a) break every
existing local CLI invocation, (b) force the local CLI to read a secret
from disk to talk to a socket it already has FS permission on, and (c) add
zero security — a process that can read a `crl_` token from
`~/.corral/config.toml` can equally read the `0600` socket. The FS
permission *is* the local auth boundary and it is stronger than a bearer
token for the local case. **The token exists solely to replace the FS
boundary that TCP does not have.**

## 5. TLS — self-signed bootstrap (`internal/tlsbootstrap`)

TLS is **mandatory** on the TCP listener; there is no plaintext-TCP code
path to misconfigure into existence.

```go
func LoadOrGenerate(dir string, hosts []string) (*tls.Certificate, error)
```

- On first listener-enable, if `<dir>/cert.pem` + `<dir>/key.pem` are
  absent, generate a **self-signed** cert: ECDSA P-256, 10-year validity,
  `hosts` as SANs (always including `localhost`, `127.0.0.1`, `::1`, plus
  the host portion of `daemon.listen` and any hostname resolvable for it),
  `KeyUsage` = digital-signature + key-encipherment, `ExtKeyUsage` =
  server-auth. Write both files mode **0600** under `<StateDir>/tls/`
  (the state dir is already `0700`).
- On subsequent starts, load the existing pair (stable cert → the client's
  pinned-CA trust in §7 keeps working across restarts).
- `daemon.tls_cert` / `daemon.tls_key` (user/env-only) override the
  location for operators who front corral with their own cert (e.g. a
  tailscale-issued or Let's-Encrypt cert); when both are set,
  `LoadOrGenerate` loads them and never generates. Absent ⇒ self-signed
  bootstrap under `<StateDir>/tls/`.

**No `Date.now()`-style nondeterminism in tests:** cert validity uses the
daemon's injected `clock.Clock` (`NotBefore = clk.Now()`), matching the
daemon-wide no-wall-clock-in-persisted-logic discipline; tests inject a
fixed clock and assert `NotBefore`/`NotAfter`.

**Self-signed ⇒ the client must trust it explicitly (§7).** A phone
browser will show a cert warning the first time (expected for a home
server); the operator accepts it once, or imports the cert. The `corral
--host` *CLI* client pins the daemon's own cert as its CA (no warning, no
system trust store mutation). tailscale users who set `daemon.tls_cert` to
a tailscale cert get a browser-trusted experience with no warning.

## 6. Opt-in TCP listener (`daemon.go`)

The listener is bound **only** if `cfg.Listen != ""`. Default config has
it empty ⇒ **no TCP port is ever opened** unless the operator opts in.
This is the single most security-sensitive line in M5 and it fails closed.

Wiring, inserted after the existing unix-socket block (`daemon.go:382+`)
and before/alongside the single `Serve`:

```go
// existing unix listener — unchanged
ln, _ := Listen(d.sockPath); os.Chmod(d.sockPath, 0o600); d.listener = ln
d.srv = &http.Server{Handler: srv.Handler()}          // unix: no auth
go d.srv.Serve(ln)

// NEW: opt-in TCP+TLS listener
if cfg.Listen != "" {
    cert, err := tlsbootstrap.LoadOrGenerate(filepath.Join(d.stateDir, "tls"), hostsFor(cfg.Listen))
    if err != nil { return fmt.Errorf("daemon: tls bootstrap: %w", err) }
    tcpLn, err := tls.Listen("tcp", cfg.Listen, &tls.Config{
        Certificates: []tls.Certificate{*cert},
        MinVersion:   tls.VersionTLS12,
    })
    if err != nil { return fmt.Errorf("daemon: listen %s: %w", cfg.Listen, err) }
    d.tcpListener = tcpLn
    d.tcpSrv = &http.Server{Handler: srv.AuthenticatedHandler(d.store, d.log)}
    go d.tcpSrv.Serve(tcpLn)
    d.log.Warn("TCP listener enabled — network-reachable", "addr", cfg.Listen, "tls", "self-signed-or-configured")
}
```

- `d.tcpListener net.Listener` / `d.tcpSrv *http.Server` are **new
  fields**; shutdown closes both servers (existing shutdown path gains the
  `tcpSrv` graceful-shutdown call, guarded by nil so the common no-TCP case
  is unaffected).
- **Startup log is a `Warn`, deliberately** — enabling a network listener
  is a security-relevant state change and belongs in the operator's face,
  not buried at info level.
- `Proxy: nil` discipline is a client concern (§7); the server side needs
  no proxy config.

## 7. Remote client — `--host` (`client.go` + `root_flags.go`)

The client refactor is small and surgical. Two hardcoded unix assumptions
become fields:

```go
type Client struct {
    httpClient *http.Client
    baseURL    string  // "http://corral" (unix) | "https://<host>" (remote)
    dialTarget string  // sockPath (unix) | "" (remote uses default TCP dial)
    authToken  string  // "" (unix) | the bearer token (remote)
    stderr     io.Writer
    // ...unchanged: warnOnce, sawDaemon
}

func New(sockPath string, stderr io.Writer) *Client            // unchanged signature; sets baseURL="http://corral", unix dialer
func NewRemote(host, token, caCertPath string, stderr io.Writer) (*Client, error) // https://host, bearer, pinned CA
```

- `do()` changes exactly two lines: URL becomes `c.baseURL + path`, and if
  `c.authToken != ""` it sets `Authorization: Bearer <token>`. Everything
  else (version headers, daemon-version warning, error envelope) is
  untouched — the whole point of centralizing in `client` (m4 §0).
- `NewRemote`'s transport: default TCP dialer, `TLSClientConfig` with a
  `RootCAs` pool loaded from `caCertPath` (the daemon's self-signed cert,
  fetched out-of-band once — `corral token create` on the server can print
  the cert path; or the operator scp's `<StateDir>/tls/cert.pem`).
  **`Proxy: nil`** (house rule — a remote corral client must not route
  through an ambient `HTTP(S)_PROXY`). `InsecureSkipVerify` is **never**
  set — a self-signed cert is trusted by pinning it as a root CA, not by
  disabling verification.
- **`--host` / `--token` / `--cacert` resolution** (`root_flags.go`): a
  single helper every subcommand calls to build its `*client.Client`.
  Precedence: explicit flag > env (`CORRAL_HOST`, `CORRAL_TOKEN`,
  `CORRAL_CACERT`) > `~/.corral/config.toml` `[client]` table > default
  (unix socket). If `--host` is set, `--token` is **required** (error if
  absent — a remote daemon will 401 anyway, but failing early with a clear
  message beats a confusing 401). If `--host` is absent, all three network
  flags must be unset (a token means nothing to the unix socket) — warn
  and ignore, don't error.
- The `[client]` config table is **user-file/env-only** — it holds a
  bearer token; a repo `.corral.toml` must never set `client.token` or
  `client.host` (added to `repo_allowlist.go` reject list alongside the
  `daemon.*` keys). The token in `~/.corral/config.toml` lives at mode
  0600 (existing rule for secrets in that file).

## 8. Web dashboard (`internal/api/dashboard`)

Greenfield, embedded, **self-contained** (no CDN, no external fonts, no
outbound requests from the browser — a phone on the same LAN as a home
server may have no working internet route to the daemon's origin).

- `//go:embed *.html *.js *.css` → an `fs.FS` served under `GET /`
  (and `/dashboard/*` for assets) via `http.FileServerFS`.
  `RegisterDashboard(s *Server)` wires it.
- **Served only on the authenticated (TCP) handler.** The dashboard is for
  remote use; it lives behind the bearer wall. Decided auth mechanism for
  the *browser* (which cannot set an `Authorization` header on a plain
  navigation): the operator opens
  `https://host/?token=<tok>` **once**; the page's inline JS immediately
  (a) stores the token in `sessionStorage`, (b) strips it from the URL via
  `history.replaceState` so it is not left in browser history/referer, and
  (c) sends it as `Authorization: Bearer` on every subsequent `fetch` and
  as a query param only on the SSE `EventSource` (which also cannot set
  headers — see §9). The static asset routes themselves (`/`, `app.js`,
  `app.css`) are served **before** the bearer check so the page can load
  and then authenticate its XHRs — the assets are non-secret HTML/JS/CSS;
  every *data* route stays behind the wall.

  > Security note recorded: serving the shell HTML/JS unauthenticated is
  > deliberate and safe — it contains no session data, only the client
  > code. All state arrives via authenticated `fetch`/SSE. A token in a
  > URL is the standard bootstrap for header-less browser contexts; the
  > `replaceState` strip is the mitigation. This is the one place a token
  > rides a URL, it is scoped to first paint, and §16 tracks
  > cookie-session upgrade as the follow-up.

- **Three views, one page (SPA, vanilla JS — no build step, no framework
  bundle to vendor):**
  1. **Session list** — table of sessions with live status
     (`running`/`blocked`/`exited`/…), name, repo, cost. Rows update in
     place from SSE.
  2. **Blocked-reason cards** — every `blocked` session renders a card
     showing `state.BlockedReason`, with an answer textarea + Send button
     that POSTs to the existing answer path (`POST
     /v1/sessions/{id}/answer` or the established route). This is the
     literal exit-criterion interaction: unblock a session from a phone.
     The answer payload is **never shell-interpolated** server-side
     (existing guarantee); the browser sends plain text.
  3. **DAG view** — for a submitted dag, the task graph with per-task
     status/cost, reusing `GET /v1/dags/{id}`. A simple dependency layout
     (no heavy graph lib — SVG or nested flexbox), live-updated from SSE.
- **Snapshot + stream, not poll:** on load the page fetches a one-shot
  state snapshot (`GET /v1/dashboard` — sessions + active dags), then opens
  the SSE stream (§9) for deltas. No polling loop.

## 9. SSE event bus (`broker.go` + `handlers_events.go`)

The first push channel in corral. A broker fans persisted events out to
live subscribers; it is a **read amplifier on top of the existing event
stream**, not a new source of truth (the store remains authoritative).

```go
type Broker struct { /* mu, subs map[int]chan Event, nextID int */ }
func (b *Broker) Subscribe() (id int, ch <-chan Event)
func (b *Broker) Unsubscribe(id int)
func (b *Broker) Publish(ev Event)   // non-blocking per sub; slow consumer dropped
```

- **Where events enter the broker:** the daemon already funnels durable
  events through `store.AppendEvent` and state transitions through
  `state.Engine`. The broker taps that single choke point — every
  `AppendEvent` (and every session-status transition) also calls
  `broker.Publish`. Decided: publish from the **same call site** that
  persists, *after* the persist succeeds, so a subscriber never sees an
  event that did not durably happen. The broker is injected into the
  Engine/store-writer, not scattered across handlers.
- **`GET /v1/events/stream`** (SSE, `Content-Type: text/event-stream`):
  subscribes, writes each event as `data: <json>\n\n`, flushes per event
  (`http.Flusher`), and unsubscribes when the request context is
  cancelled (client disconnect). A heartbeat comment (`: ping\n\n`) every
  ~20s keeps intermediaries from idling the connection closed.
- **Slow-consumer policy (decided): drop, never block.** Each subscriber
  has a small buffered channel; `Publish` does a non-blocking send and, on
  a full buffer, drops the event for that subscriber and flags it stale.
  A dropped subscriber's next successful send is preceded by a
  `resync` event telling the page to re-fetch the snapshot. **The broker
  must never block the persist path** — a slow phone on a bad connection
  can never wedge the daemon's event writes. This is the SSE analogue of
  the m4 "corral must never perturb the agent" rule.
- **Auth:** SSE runs on the authenticated TCP handler. Because
  `EventSource` cannot set an `Authorization` header, the stream endpoint
  accepts the token as a query param **on this route only**
  (`/v1/events/stream?token=…`), verified by the same
  `VerifyToken` — the token is already in `sessionStorage` from §8's
  bootstrap. Recorded trade-off: a token in a query string can land in
  server access logs; corral's own request log **must redact the `token`
  query param** for this route (add to the existing redaction pass), and
  §16 tracks the cookie-session upgrade that removes the query-param token
  entirely.
- **Payload redaction:** events are already secret-scanned/redacted before
  persistence (existing ingest rule); the broker forwards the
  already-redacted stored form, so no new redaction surface is introduced.
  The broker MUST forward the persisted (redacted) event, never a
  pre-redaction in-memory copy.

## 10. Per-session scoped child tokens (step 34)

RUNBOOK §7: "per-session scoped tokens so a child agent can only manage its
own subtree." The schema carries `scope`/`session_id` from step 26; step
34 turns on **enforcement**.

- A `scope='session'` token has a non-NULL `session_id` naming the
  **subtree root** (a session, or a dag's root task). Such a token may
  call read/write routes **only** for that session/dag and its
  descendants; every other target ⇒ 403 `CodeForbidden`.
- Enforcement point: a small authorization helper consulted by the write
  handlers (answer, kill, submit-child-dag), reading the `TokenRow` the
  auth middleware stashed in the request context (§4). Subtree membership
  is resolved via existing task/dag parentage (`task_deps` / `dag_id`) —
  no new graph state.
- **How a child agent gets its scoped token:** when the orchestrator
  spawns a headless task that is itself allowed to call the API, it mints a
  `scope='session'` token rooted at that task and injects it via
  `BuildEnv` (like `CORRAL_SESSION_SECRET`/`CORRAL_SOCK` — **inside
  `BuildEnv`, never stuffed into `spec.Env` after**, per the m4
  BuildEnv-invariant rule). The child's token can answer/kill only within
  its own subtree; it cannot touch a sibling agent's session. `envWhitelist`
  continues to exclude the raw secret; the scoped token is a distinct
  variable governed the same way.
- **Admin tokens (`scope='admin'`, the operator's phone/laptop tokens)
  bypass the subtree check** — they are full-access by definition. Only
  `scope='session'` tokens are confined.
- This is the one step severable to v0.5.1 (§1); if severed, all tokens
  are admin-scoped and the exit criterion is still met. The schema and the
  context-stashed `TokenRow` mean severing costs no rework — only the
  helper and the orchestrator mint call are dropped.

## 11. CLI surface

```
corral token create --label <name> [--scope admin|session] [--session <id>]   # prints plaintext ONCE
corral token list                                                              # id, label, scope, created, last-used, revoked
corral token revoke <id>

# every existing subcommand gains remote targeting:
corral --host <addr> --token <tok> [--cacert <path>] ls
corral --host <addr> --token <tok> attach <id>
corral --host <addr> --token <tok> run "<prompt>" --repo <path>
# ...etc; --host/--token/--cacert are global, resolved once (§7)
```

- **`corral token create` is a local-admin operation** — minting a token
  is done over the **unix socket** (the operator is on the box, or over an
  already-authenticated `--host` session). It hits `POST /v1/tokens`,
  which returns the plaintext exactly once in the response body; the CLI
  prints it and warns it will not be shown again. Over TCP this endpoint
  requires an existing admin token (bootstrapping the *first* token is a
  local-socket operation by design — you mint your first token on the
  server, then use it from your phone).
- **`corral token list` / `revoke`** never expose plaintext or hash.
- The `token` command follows the `cmd_new.go` / `cmd_answer.go` file
  shape; `--host`/`--token`/`--cacert` are parsed in a shared
  `root_flags.go` helper (§7) so all subcommands share one resolution path
  rather than each re-parsing.
- **No repo-file channel for any of this** — `client.host`/`client.token`
  and the `daemon.listen`/`daemon.tls_*` keys are all user/env-only,
  rejected from repo `.corral.toml` (§7, §12).

## 12. Config + trust boundary

New `DaemonConfig` fields (user-file/env-only):
- `daemon.listen` (string, default `""` ⇒ no TCP) — `CORRAL_DAEMON_LISTEN`
- `daemon.tls_cert` / `daemon.tls_key` (string, default `""` ⇒ self-signed
  bootstrap) — `CORRAL_DAEMON_TLS_CERT` / `CORRAL_DAEMON_TLS_KEY`

New `[client]` table (user-file/env-only):
- `client.host` / `client.token` / `client.cacert` — `CORRAL_HOST` /
  `CORRAL_TOKEN` / `CORRAL_CACERT`

**`repo_allowlist.go` additions (mandatory, load-bearing):** every one of
the above is added to the reject list, exactly as `daemon.socket` etc. are
today. A repo `.corral.toml` that sets `daemon.listen` (opening a port),
`daemon.tls_cert` (swapping a cert), or `client.token` (leaking/planting a
bearer token) is **dropped and reported as a Rejection** — never merged.
This closes the obvious attack: a cloned malicious repo that tries to make
the daemon network-reachable or exfiltrate via a planted token. A
regression test asserts each new key is rejected (mirroring the existing
`daemon.*` rejection tests).

Secrets in `~/.corral/config.toml` (now including `client.token`) stay at
mode 0600; the token is never logged.

## 13. Security review (the network surface, enumerated)

This section is the checklist a network-facing milestone owes. Each item
is a decided posture, not an open question:

1. **Default-closed.** No TCP port unless `daemon.listen` is explicitly
   set by user/env config. Verified by a test asserting a
   default-config daemon binds only the unix socket.
2. **TLS mandatory, no plaintext-TCP path.** `tls.Listen` is the only TCP
   bind; there is no code branch that serves HTTP over TCP.
3. **Token required on TCP, constant-time verified, timing-oracle-free.**
   Reuses the hook-auth idiom (§4). Missing/wrong/revoked/malformed all
   return an identical 401 in body and (as far as feasible) timing.
4. **Tokens hashed at rest (SHA-256), plaintext shown once, never logged,
   never returned by reads.** No token material in any event, log line, or
   list response.
5. **Repo trust boundary extended.** `daemon.listen`/`daemon.tls_*`/
   `client.*` are repo-rejected (§12) — a cloned repo cannot open a port,
   swap a cert, or plant a token.
6. **Local socket unchanged and still default.** FS-perm auth, `0600`, no
   token, no regression to the existing local CLI.
7. **Slow/hostile client cannot wedge the daemon.** SSE drops slow
   consumers; the broker never blocks the persist path (§9).
8. **`Proxy: nil` on the remote client**, `InsecureSkipVerify` never set —
   self-signed trust is via pinned-CA, not disabled verification (§7).
9. **Dashboard shell is unauthenticated (non-secret code); all data is
   behind the bearer wall.** The one URL-borne token (first paint + SSE
   query param) is stripped from history and redacted from request logs;
   cookie-session upgrade tracked in §16 (§8, §9).
10. **Scoped child tokens confine agent-spawned agents to their subtree**
    (step 34), injected via `BuildEnv` under the existing invariant (§10).
11. **No new merge/push/write-to-user-repo capability.** M5 adds no
    mutation of user git state; the dashboard's DAG view and `corral
    review` remain read-only. The answer path is the only new remote
    write, and it flows through the existing (three-way-gated,
    never-shell-interpolated) answer machinery.

Advisor consult on this surface: **the architecture was pressure-tested
before authoring** (per the global escalation rule) and the blocking
concern raised — that opening a TCP port is the one hard-to-reverse,
outward-facing action — is resolved by the default-closed posture (item 1)
plus the explicit `Warn` at bind time (§6). The design doc itself was
authored before any listener code, and the bind default + TLS posture were
confirmed with the user before this step.

## 14. Test + fuzz mapping

- **apitoken**: `Mint` produces distinct 256-bit tokens (no collisions
  across N mints); `Verify(plaintext, hashOf(plaintext))` true; `Verify`
  of a tampered plaintext false; `Verify` constant-time (compare uses
  `subtle`). `FuzzVerify` — never panics on arbitrary plaintext/hash.
- **tlsbootstrap**: `LoadOrGenerate` on an empty dir produces a valid
  self-signed cert with the requested SANs, files at 0600; a second call
  loads the *same* cert (stable across restart); an explicit
  cert/key path is loaded and never regenerated; `NotBefore` uses the
  injected clock.
- **middleware_auth**: missing header / malformed header / unknown token /
  revoked token → 401 with byte-identical body; valid token → passes,
  `TokenRow` in context, `EventTokenUnauthorized` appended on each failure
  with **no token material**; unix handler path has no auth applied.
- **store/tokens**: create/verify/list/revoke round-trip; revoked token
  fails verify; `ListTokens` never returns `token_hash`; verify of a
  never-created plaintext returns `(_, false, nil)` not an error.
- **daemon TCP listener**: default config → no TCP bind (only unix); with
  `daemon.listen` set → a real TLS+bearer listener answers `GET
  /v1/version` only with a valid token and 401s without; shutdown closes
  both listeners.
- **client remote**: `NewRemote` sets `Authorization: Bearer` and an
  `https://host` base; pinned-CA trust verifies the daemon's self-signed
  cert; `Proxy` is nil; `InsecureSkipVerify` is false.
- **repo_allowlist**: `daemon.listen`, `daemon.tls_cert`, `daemon.tls_key`,
  `client.host`, `client.token` each rejected from a repo file (table test
  extending the existing `daemon.*` rejection test).
- **broker**: subscribe→publish→receive; unsubscribe on context cancel;
  slow consumer dropped (buffer full) and gets a `resync`, never blocks the
  publisher; publish happens only after persist.
- **SSE endpoint**: streams `data:` frames, flushes per event, closes on
  disconnect; token required (query param), redacted from the request log.
- **dashboard**: assets served (index 200, `app.js` correct content-type);
  data routes 401 without token; the answer POST reaches the existing
  answer path.
- **E2E (exit criterion)**: a real daemon with `daemon.listen` set, TLS
  self-signed, one token minted; a scripted remote client (and, gated,
  a real browser via chrome automation) opens the dashboard with the
  token, sees a session go `blocked` live over SSE, submits an answer from
  the card, and observes the session unblock — the literal "manage a
  session from a phone browser." Gated real-browser leg behind
  `CORRAL_E2E_BROWSER=1`; the scripted-HTTP leg always runs.
- **NEVER touch the real `~/.claude` or the real `~/.corral`** — tests use
  temp HOME/state dirs and hand-authored config, per the standing rule.

## 16. Deferred (with sequencing)

- **Token TTL / auto-expiry + rotation** — v0.5.0 tokens are revocable but
  not auto-expiring. Add `expires_ms` + a rotation command once the
  operator flow is exercised. → v0.5.x.
- **Cookie-session for the browser** — replaces the URL/query-param token
  bootstrap (§8/§9) with a `Set-Cookie` session after a login POST,
  removing the token from URLs entirely. → v0.5.x, next after the
  dashboard lands.
- **mTLS / client certificates**, **OIDC / SSO**, **CORS for third-party
  origins** — not needed for a same-origin, single-operator home-server
  dashboard. → later, only if a multi-origin/SSO deployment is ever a
  goal.
- **Multi-user / RBAC** — one operator, N equally-privileged admin tokens
  (plus confined session tokens). Real per-user roles are a much larger
  surface. → later.
- **Dashboard richness** — live log tail, cost charts, session creation
  from the UI. v0.5.0's dashboard is the exit-criterion minimum (list,
  unblock, DAG view). → v0.5.x.
- **tailscale-native identity** — v0.5.0 supports tailscale operationally
  (set `daemon.tls_cert` to a tailscale cert, bind `daemon.listen` to the
  tailscale IP) but does not *integrate* tailscale identity (using
  tailscale's caller identity in place of a bearer token). → later.
- **Rate limiting / fail2ban on 401s** — the constant-time 401 defends the
  token; a network-facing daemon may later want connection-level throttling
  of auth failures. → v0.5.x hardening.
