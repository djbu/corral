# Evidencia de dogfood M8

**Fecha:** 2026-08-10. **Base:** `v0.7.0` (`bca30e3`).

## Ciclo real por CLI

`scripts/release/smoke-review.sh` construye el binario actual y `fakeclaude`,
arranca un daemon aislado y somete DAGs reales mediante `corral run --worktree`.
La ejecución comprobó:

- terminar una tarea sólo crea `pending_review`; el repo principal no recibe
  el archivo antes de una acción humana;
- preflight de merge devuelve identidades exactas y release integra el commit;
- un restart del daemon conserva el review pendiente;
- discard crea una ref `refs/corral/recovery/...`, retira el worktree y conserva
  la rama;
- dos DAGs con el mismo nombre de tarea en el mismo repo no colisionan;
- un conflicto bloquea el release y el HEAD destino queda byte por byte igual.

El mismo smoke forma parte de CI en macOS y Linux. El harness de upgrade acepta
RCs `v0.8.0-rc.N`, parte del tag estable `v0.7.0` y exige migración de schema 6
a schema 7 con intención de sesión preservada.

## Dashboard en navegador real

Se ejecutó `scripts/release/serve-review-browser.sh` con daemon TLS, bearer admin
y una tarea pendiente. El navegador embebido no acepta una CA efímera no
confiable; para no desactivar su seguridad, la navegación usó el proxy loopback
de prueba `test/reviewproxy`, que fija el certificado del upstream TLS. El
daemon siguió recibiendo HTTPS autenticado.

En el navegador se comprobó:

- bootstrap del token y carga del dashboard;
- apertura del DAG, diff completo e identidades repo/worktree/rama/base/HEAD;
- selección de estrategia, preflight y habilitación condicionada de Release;
- refresh por SSE al someter otro DAG, sin recargar la página;
- estado final `succeeded · released` después de ejecutar la misma operación
  contra el fixture.

El controlador del navegador no pudo aceptar el diálogo nativo
`window.confirm`; el POST de release/discard está cubierto por tests HTTP reales
y por el smoke CLI contra el mismo servicio. No se instaló una CA ni se evitó
una advertencia TLS.

## Gates deterministas

- tests Git reales para merge, cherry-pick, conflicto sin mutación, carrera de
  HEAD, descarte recuperable y force con identidad exacta;
- tests del store para transición atómica y compatibilidad legacy;
- tests HTTP para rutas, scopes y rechazo de mutaciones con token no admin;
- contrato estático del dashboard y validación sintáctica de JavaScript;
- `go test -race ./...`, `go vet ./...` y build estático como gates de CI.
